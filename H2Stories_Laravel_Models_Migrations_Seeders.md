# H2Stories Laravel database files

This document contains the complete H2Stories Laravel models, migrations, commands, and role seeder.

## Naming applied

- Removed the `TM_` prefix from every new table.
- Used Laravel's matching naming convention: `PractitionerVerification` model → `practitioner_verifications` table.
- Added explicit `$table` values in the models so the mapping is unambiguous.
- Provides updated contents for Laravel's existing `app/Models/User.php`, users migration, and `DatabaseSeeder.php`. Edit those files directly; do not run Artisan to recreate them.
- Created no models for `user_roles`, the eight pure testimonial mapping tables, or the circular foreign-key migration.
- Created a seeder only for stable reference data (`roles`). Transactional/user/client/testimonial records must not be fabricated in production seeders.

## Important before migration

1. These are fresh-build baseline migrations. The workbook marks database tasks as **Done**, so compare these files with the real database before running them. Use additive/alter migrations if tables already contain data.
2. Do not use `php artisan migrate:fresh` on the shared H2Research database.
3. The eight mapping migrations intentionally store and index H2Research IDs without guessing their foreign table names or key types. After inspecting the actual H2Research schema, change each related ID column to the exact parent type and add the correct foreign key.
4. Confirm the existing connection uses InnoDB and compatible `utf8mb4` collation.
5. Migration order matters. `testimonials` must be created before `testimonial_versions`; the separate latest-version foreign-key migration must run after both.
6. The default Laravel users migration in this document keeps the existing `password_reset_tokens` and `sessions` tables. Do not create duplicate migrations for them.
7. Validate `years_of_experience` as nonnegative in the Form Request. Add a database `CHECK` constraint only after confirming the deployed MySQL version and existing data.
